# 相同事件 30 秒冷却

占用、环境、模型事件在进入 `0x20` 队列前共用一次冷却。键是 `event_type`、`zone_id`、`env_ch`。距该键上次成功入队不满 30 秒的一条丢掉。满 30 秒，或这把键还没有成功入队过，照常入队。

边沿规则、模型「类名不变不再填事件」、队列长度 24、队满丢最新，都保持不变。

## 键和窗口

键相等的条件是：`event_type` 按 C 字符串相等，`env_ch` 按 C 字符串相等，并且 `zone_id` 相等。比较不超过各自字段长度；字段里没有结尾 0 时，比到字段容量为止。空字符串也参与比较。`purpose`、人数、读数、目标列表不参与。

窗口是 30000 毫秒，从该键上一次成功写入队列的时刻算起。

- 已过去的毫秒数小于 30000：丢掉。不入队，不改上次时间。
- 已过去的毫秒数大于或等于 30000：入队，并把上次时间改成现在。
- 表里没有这把键：入队，并记下现在。

被丢掉的进出房、进出区、越阈、恢复不会补发。边沿状态已经按这一帧推进。模型侧同一次类名变化也不会在下一拍再试。

## 入队结果

检查放在 `peer_judge` 内部入队和 `peer_judge_push` 共用的加锁路径上。模型任务和快照任务同时入队时，冷却表和队列用同一把锁。

`peer_judge_push`：

- `ev == NULL`：返回 false。
- 冷却丢掉：不入队，返回 true。调用方把这一次当成已经处理完。模型因此更新该区上一拍类别。
- 队列已有 24 条：不入队，不记冷却时间，返回 false。队头不变。
- 成功写入：返回 true。

`peer_judge_reset` 在同一把锁里清掉冷却表。清空之后，同一把键可以立刻再入队。

## 时钟和表

设备上用 `esp_timer_get_time()` 换算的毫秒。不用 `utc_unix_s`。

自检在同一文件里把「现在」设成指定毫秒，避免开机自检真的等 30 秒。无论自检成败，返回前都关掉这个覆盖，之后仍用 `esp_timer`。PC 自检没有 `esp_timer`，只使用这个毫秒计数。

冷却表 32 槽，线性查找。32 槽都占用时，覆盖 `last_ms` 最小的那一槽；有多槽时间相同则覆盖先找到的那一槽。槽位数量是上限：同时留在 30 秒窗口里的不同键超过 32 把时，最旧的一把会被当成没报过。

## 自检

仍在 `peer_judge_selfcheck` 里，不新增测试文件。

- 同一键在 0 ms 入队后，29999 ms 再推一次：返回 true，队列仍是 1 条。30000 ms 再推一次：队列变成 2 条。
- 10000 ms 那次被丢掉，不把窗口推迟。因此从 0 ms 算起，30000 ms 仍然可以入队。
- 只改 `zone_id`，或只改 `env_ch`，在窗口内也入队。
- `peer_judge_reset` 之后，同一时间、同一把键可以再次入队。
- 队列满：24 条 `event_type` 都是 `resting`，`zone_id` 分别为 0 到 23。第 25 条返回 false，队列长度仍是 24，队头的 `zone_id` 仍是 0。

## 文档

`peer_judge.h` 里 `peer_judge_push` 的说明改成：冷却丢掉返回 true；只有空指针和队列满返回 false。
